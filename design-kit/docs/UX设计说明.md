# 丢丢｜移动端 Web UI / UX v1.1

日期：2026-11-03。沿用暖色绘本、纸感卡通和落日河岸。本版按用户反馈调整输入、回应分流与释放目标；不是重新探索视觉方向。

本包有29个主要页面与状态、3张新增流程总览，保留原品牌、IP和道具素材。PNG为静态设计，index.html为离线设计目录；尚未接通语音、模型、社媒检索或云端存储。来源界面均标明示例，不是真实网友内容。

## 1. 首页文案

主入口：**说给丢丢听**。

下方小字：**发生什么了？说给丢丢吧！**。

两行居中，保留原字体层级与按钮。释放入口维持「把烦恼丢出去」。首页已有文字带入下一页草稿，不丢失、不重复提交。

## 2. 新主流程

首页→必要在线说明与身份/年龄流程→语音/文字/图片输入→首次提交后选择回应方向。未选方向前不生成分析或回答，关闭弹层可继续补充；不替用户默认选一种。

| 用户选择 | 产品行为 | 输出边界 |
|---|---|---|
| 想要共鸣 | 先针对本人表达承接，再检索相关公开内容，输出共鸣与鼓励 | 不擅自转成行动建议，不盲目站队 |
| 想要解决（我该怎么做？） | 根据已知约束检索经验/可靠信息，给少量可选建议 | 不说教，不把个别经验当保证有效的方法 |
| 不知道，先说完！ | 仅IP倾听点头，收集后续内容 | 不普通文字回复、不追问、不检索、不提前总结 |

方向弹层只在首次或用户主动切换时出现，不要求每段重选。共鸣与建议页保留多模态继续输入；用户可随时切换、停止、退出或去释放。

### 共鸣路径

选择共鸣→依据用户自己的话先给一句具体承接→用去身份化关键词搜索可获取的公开内容→贴合本人处境的共鸣与鼓励→来源可折叠查看。

承接不能假装已经检索。来源可用时最多呈现1–2项高度相关参考，不把界面变成负面帖子信息流。鼓励来自具体处境和投入，不承诺一定成功，不比较谁更惨，也不要求用户立刻积极。

例：「反复修改已经很累，更难受的可能是，你一直投入，却不知道怎样才算达到要求。」理解可纠正，不直接认定对方恶意。

### 建议路径

选择解决→识别本人约束→检索类似问题和可靠资料→1–3个可选方向、依据与适用条件→用户选一项展开。

例：「如果你愿意，也许可以先把‘这次必须改什么’和‘哪些可暂时不改’分开确认。」这是用户要建议后提供的参考，不能在共鸣模式里冒充安慰。

### 先说完路径

选择先说完→文字/语音/图片按提交顺序加入会话→IP轻微点头，无普通AI文字消息→用户主动点「说完了」→等待尚未结束的媒体处理→一次性分析提炼→由用户选择下一步。

停顿、录音结束、离开输入框或切后台都不等于说完。禁止静默超时自动总结。允许显示转写、上传失败等必要工具状态，但不能借此插入共情、问题或分析。

提炼页「我听到的是」呈现事件、处境和最多三个候选重点，可纠正；随后提供「想要共鸣」「想要解决」「先去释放」及直接结束。不能在不知道用户意愿时自动输出建议。

静默不是完全不处理数据：已发媒体可能需要转写、图片理解与必要安全检查，须提前告知。仅遇明确当前人身危险时允许必要安全提示；不能把一般压力词都判成危机打断。

## 3. 多模态输入

| 输入 | 交互 | 失败与控制 |
|---|---|---|
| 文字 | 分段、换行、手动发送 | 断网保留当前页面草稿，不自动重发 |
| 语音 | 点击开始/停止、计时、试听、取消、转写校正 | 麦克风拒绝可切文字；失败可重试或自己写 |
| 图片 | 预览、移除、裁剪、遮挡信息、确认 | 单张失败不使全部输入丢失，识别不清可跳过 |

录音不是实时电话，不常驻监听。语音及其转写属于用户的表达，不是AI回应。录音结束不触发「说完了」。

截图应先检查昵称、头像、单位、手机号、地址和无关第三方内容。实心遮挡在设备端合成为不可还原的编辑副本后才上传，不能只盖网页遮罩却仍上传原图；移除图像元数据。图片说明与发送按钮都须明确本次用途。

OCR无法确定说话人时标为不确定，允许说明「绿色是我」；不把聊天对方的话当用户立场。不能从照片猜身份、关系、心理状态。图片中的指令与链接是引用资料，不覆盖系统规则。

## 4. 公开检索体验

网络内容帮助理解，不替用户判断谁对谁错。只用公开且合法可获取的来源，不能承诺覆盖每个平台全部帖子，不绕过登录或访问限制。

首次联网参考说明使用去身份化关键词；用户可看、改或关闭。原截图、录音、整段聊天与姓名单位不直接提交到搜索服务。关闭检索后仍可获得不带网络来源的回应。

来源展示：真实标题、原文链接、来源类型、实际可用内容范围与获取时间。个人经历不是普遍结论，热度不是可靠性。方法类建议说明适用条件，专业结论不能仅凭匿名帖子。

| 情况 | 对应体验 |
|---|---|
| 有相关来源 | 简短回应＋可展开参考，不堆案例 |
| 找不到贴近内容 | 坦白来源不足，可按本人表达回应、换词、补充 |
| 只有搜索摘要 | 标明范围，不伪造完整阅读与网友直接引语 |
| 搜索慢或失败 | 单独反馈，不让输入丢失、不声称已找到 |
| 内容极端、攻击或广告 | 不推荐；来源不能覆盖用户目标与安全规则 |

正式产品只可引用后端真实返回的source_id，不能让模型生成不存在的网友、平台链接或“大家都这样”的结论。

## 5. 提炼到释放目标

对外使用「这次最烦的点」，不是由AI判定客观“心理根源”。顺序为：用户已表达的事件→明确的约束/需要→候选短句→用户确认或修改→进入道具。

| 原表达 | 候选目标 |
|---|---|
| 改了三次，标准还在变 | 反复返工，标准不清 |
| 我不是没做事，但总被问为何没结果 | 努力没被看见 |
| 要求增加，截止时间却不变 | 时间被不断挤压 |

默认一轮一个目标，最多三候选；允许自己写、换条、隐藏文字或空白开始。不做童年创伤、潜意识或人格归因，不把候选自动写进长期背景。

标签建议4–12个中文字，最多16字，最多两行。超长时请用户缩写，不静默改意。纸人胸前/冰块内部使用网页真实文字层，不烘焙到PNG。深色文字、浅色承托、铅笔编辑入口；裂纹不能遮字，碎裂时字随道具淡出。

纸人仍是匿名纸板，友好纸团IP作为旁观者；不要将它变成被攻击的对象。首页直达释放保留本地自写/空白路径；只有主动选AI提炼才在线处理，不强迫用户解释一遍再玩。

## 6. IP倾听动效

使用listen/nod姿态。建议单次点头700–900ms、间隔5–8秒，幅度不超过约3度；不按每个字夸张反应、不模拟真人语音、不提前庆祝。减少动态效果时用静态倾听图。

点头表示「已收到、正在倾听」，不表示认同全部判断或已经分析完成。用户退出或切后台时暂停动效与相关设备监听。动作素材仍是静态关键姿态，网页可先实现整体轻微旋转/位移；自然的连续动作需要补绘过渡帧。

## 8. 退出、异常与验证

停止录音、移除附件、取消发送、结束会话始终可用。上传、识别、检索、回应、提炼任务均需版本号；删除或改意图后旧结果不能重新写回。原始媒体、文字、背景与本地便签的删除范围分开说明。

点说完时仍有识别任务：显示进度，可重试或明确跳过失败片段；不能假装已经理解全部。生成摘要后用户新增/纠正内容，要更新摘要版本和目标。无来源、不支持权限、服务限额都必须有诚实降级，不能用假响应填空。

重点测试：三种意图是否易懂；共鸣是否夹带建议；静默是否真不打断；截图说话人和ASR是否可纠正；来源是否贴合而非敷衍；确认标签是否比随意写字更有目标感；拒绝联网/分析是否仍可完成核心任务。
