# 媒体识别与分平台搜索

日期：2026-11-04。

## 当前交互

首页保留倾听与释放入口，移除文字输入框。登录后点击“说给丢丢听”，才进入统一的文字、图片、录音输入页。

同意联网后，图片识别出的文字与客观画面、录音转写结果一起进入回应、关键词分析和烦恼提炼。纯图片或纯语音也能进入识别流程；不把文件占位符当成读懂内容。不确定的识别结果不当作确定事实，尤其不把截图里别人的话自动归到你身上。

对话中可以展开“图片和录音里读到的话”，修改不准确的识别结果。改后会用于后续理解，不自动重新上传原文件。识别结果随主动保存的文字记录保存在小纸篓；原图片、录音仍需另勾选才保存。

“不知道，先说完！”期间只收集输入，不调用识别、回应或搜索。点击“就说到这儿吧”后，才在同意范围内识别附件、整理重点。

## 云端配置

所有变量在 CloudBase → diudiu 环境 → 云函数 → **diudiu-ai** → 配置中设置。更新代码不覆盖已有变量。密钥不写入前端或仓库。

- 图片默认使用 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`；可选 `VISION_MODEL` 指向同一 Key 下支持图片的接入点。
- 音频采用用户选择的 `AUDIO_MODEL`，指向同一方舟 Key 下支持音频理解的模型或推理接入点。沿用 `LLM_BASE_URL` 的 Chat Completions 接口，传 `input_audio`，纯 Base64 与 `format: wav`。不能把仅支持文字/图片的模型当作语音模型。
- 可选另一条路径：`ASR_API_KEY` 为豆包语音服务密钥，需有录音文件极速版权限；可选 `ASR_RESOURCE_ID`，默认 `volc.bigasr.auc_turbo`。配置该 Key 时优先使用固定官方语音识别接口。方舟 Key 与语音服务 Key 不混用。

浏览器将已检查的图片转换为最多 1600px 的 JPEG，每份不超过约 1.5MB。录音转换为 16kHz 单声道 PCM WAV，每 30 秒一段；最长 120 秒，每段分别识别，再合并原话。媒体只以 Base64 发送至受登录保护的云函数，不创建公开媒体链接，不接受客户端传来的外部文件 URL。

识别请求按账号单独限流、按请求 ID 去重。退出、切换方向或停止等待后，旧结果不进入新会话。失败不会用预设识别结果兜底；可以重试或主动改用文字。

## 为何之前只有微博

原流程把小红书、微博、抖音合在一个站点范围内，只取排序靠前的少量结果，有一条可用内容就停止；容易被微博占满。现在分别限定平台域名，最多用两组关键词尝试每个平台，再按平台交错合并，最多保留 6 条来源。结果为空的平台不会用其他平台替代。社媒均无可用正文或摘要时才补充公开网页；授权失败或限流时不继续盲目补查。

来源页可以按小红书、微博、抖音筛选，没有结果时直接说明暂未找到相关公开内容。检索词、处理步骤、调用计数不出现在界面。

这仍是豆包搜索对公开网页的检索，不是三个 App 的站内全量搜索。登录后的笔记、评论、视频字幕、未收录网页不保证可检索。需要稳定、完整覆盖时，需要另行取得平台允许的内容接口或合规数据源，不能据此承诺抓取完整站内内容。

## 实际验证

已用合成中英文截图验证现有图片模型真实识别成功。独立 `AUDIO_MODEL`（用户选择 Doubao-Seed-2.0-mini-260428）已将有效合成英文录音准确转成原话，取得实际 token 用量 211。早期联调样本为空 WAV，导致 InvalidParameter；已更换有效样本并增加空 WAV 前置校验，不能将该次错误归因于模型不支持音频。中文真人录音与真机兼容性尚待验证。

一组虚构学术压力查询分别尝试了三个平台，共 5 次搜索：微博返回 5 条可用内容，小红书与抖音均返回空。此结果只说明这次查询的接口实际返回，不能推断所有主题永远搜不到。

浏览器测试 `tests/browser-recognition.mjs` 覆盖媒体单独输入、联网同意、WAV 转换、识别内容参与上下文、手工修正、避免重复上传、本地保存和静默结束后再识别。测试桩不等于真实模型验证。

已发布页面的 `tests/live-recognition-ui.mjs` 也通过图片与语音混合输入 → 实际识别 → 真实回应 → 多选烦恼提炼，无识别结果或应用会话测试桩。31 项单元测试通过。线上媒体联调脚本使用本机忽略目录的账号及合成 WAV，不提供任何私人录音或账号文件到仓库。
