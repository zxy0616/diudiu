# 丢丢｜产品策划案

版本：v1.1（已核验 UX v1.1 原包，补齐冲水与纸人结束规则）  
日期：2026-11-04  
交付形态：移动端 Web 交互体验版 + 可扩展的真实服务接口方案

## 1. 产品定位

丢丢是一款以纸团 IP 为情绪陪伴载体的轻量产品。用户可以把难以消化的日常烦恼说出来，选择此刻需要的回应，再通过具象的释放互动，暂时放下情绪负担。

核心主张：**先由用户决定需要什么，再由丢丢回应。**

产品提供情绪表达、陪伴和建议参考，不承担心理诊断与治疗，不承诺消除烦恼，不把情绪好转作为必须完成的任务。

### 1.1 目标用户与场景假设

- 日常遇到人际、学习、工作或生活烦恼，希望拥有低压力表达空间的人。
- 不方便向熟人开口，担心被评价、被说教或被过早打断的人。
- 暂时不需要建议，只想完整讲述，或想通过短暂互动释放情绪的人。

以上是待验证的人群假设，不代表已经完成用户研究。优先围绕非紧急的日常烦恼验证体验。

### 1.2 产品目标

1. 降低开口成本：文字、语音和图片可组合表达。
2. 提高回应自主权：输入后选择共鸣、解决或先说完。
3. 降低被打断感：静默模式只通过 IP 倾听动作反馈。
4. 提高释放目标感：纸人靶子和冰块显示用户确认的烦恼重点。
5. 建立可信边界：真实来源、演示内容、用户输入与 AI 推测清楚区分。

### 1.3 不应出现的体验

- 用户选择共鸣，却立即收到行动清单。
- 用户选择先说完，却收到追问、摘要或分析文字。
- 把检索到的个体经历说成普遍结论，把 AI 推测说成确定的心理根源。
- 用连续签到、排行榜或催促通知，让情绪表达变成任务。
- 将用户的倾诉、截图或录音提交到公共仓库。

### 1.4 产品价值与验证假设

丢丢的价值假设由三部分组成：用户控制回应方向，降低被打断和被说教的压力；纸团 IP 提供低语言负担的陪伴反馈；用户确认过的烦恼文字连接倾诉与释放，形成连续体验。

这不是已经证实的竞争优势。第一轮可邀请少量自愿体验者，分别完成“只想被理解”“还没说完”“想要建议”“直接释放”四类任务，记录理解偏差与退出原因。访谈不要求提供真实敏感经历，可以使用虚构情境。

### 1.5 运营与商业化建议

交互验证阶段不引入付费墙、广告、排行榜和付费解锁回应。先验证用户是否愿意开口、是否理解三方向、是否认可倾诉到释放的连接，再决定投入真实服务。

如进入正式运营，可评估自愿购买的外观主题、IP 周边或增强服务等方向；不将基础情绪支持与危机帮助设为付费门槛，不以延长负面情绪停留时间提高收入。这些仅是后续讨论方向，本次不实现交易、订阅或营销通知。

## 3. 功能架构

### 3.1 首页

- 倾听入口：**说给丢丢听**。
- 倾听入口小字：**发生什么了？说给丢丢吧！**
- 释放入口：**把烦恼丢出去**。
- 两个入口的主副文案均居中对齐。
- 保留纸团 IP 和原河岸视觉；具体构图以原稿为准。
- 历史记录、背景记忆与设置按原稿核验后放置，不自行增加一级导航。

### 3.2 说给丢丢听

多模态输入 → 选择回应方向 → 对应陪伴分支 → 提炼并确认烦恼重点 → 可选进入释放。

### 3.3 把烦恼丢出去

已有烦恼重点或手动填写 → 确认文字 → 选择玩法 → 自主互动 → 自愿结束 → 可选记录当下感受。

三类玩法：纸团投掷（纸人靶子）、一口气冲走（冲水）、敲碎情绪冰（砸冰块）。允许手写目标或不写字直接开始。

### 3.4 背景记忆与隐私

背景记忆供用户主动管理长期背景；与临时倾诉分开。保存、编辑、删除和关闭记忆均由用户控制。第一版仅在用户明确选择保存时写入当前浏览器，不默认持久保存原始截图和录音。

## 4. 核心 UX 流程

### 4.1 首次进入

首页直接展示两项主入口。第一次准备发送内容时，用简洁说明告知：当前为交互演示、文字和图片默认仅在本地处理、未接入真实 AI 和外部检索。语音如使用浏览器厂商联网识别，必须在开启前单独告知并取得同意，不能包含在“仅本地”的承诺中。用户无需注册或填写个人资料即可体验。

不把长篇条款放在倾诉开始前；隐私说明可随时查看。发布实际联网版本前需同步修改告知文本，不能沿用“仅本地”的演示声明。

### 4.2 输入烦恼

1. 用户进入倾诉页，可以输入文字、添加图片或主动开启语音。
2. 图片发送前显示预览，允许移除，并提示检查姓名、头像、联系方式等隐私信息。
3. 用户可组合输入；发送按钮仅在有有效内容时可用。
4. 首条内容提交后，先显示三种回应方向，不默认生成答案。
5. 用户选好方向后，可继续补充，或主动切换回应方向。

语音仅在用户操作后请求麦克风权限。权限拒绝、设备不支持、未识别出内容时，提供文字输入入口，不生成虚构转写。

### 4.3 回应方向选择

三项选择保留原意与文案：

- **想要共鸣**：先被理解，暂时不需要解决办法。
- **想要解决（我该怎么做？）**：获得温和、可选择的建议参考。
- **不知道，先说完！**：丢丢安静听，用户决定何时结束讲述。

选择仅作用于当前会话，可随时更改，不作为用户人格标签。

### 4.4 共鸣分支

真实服务目标流程：

1. 从用户内容中提取最小必要、去身份化的检索主题。
2. 在外部检索前展示拟用关键词，允许编辑、取消或不检索继续。
3. 仅使用可合法访问的网络内容，不要求用户提供社媒账号，不绕过登录和访问限制。
4. 将相似经历作为“也有人有相似感受”的参考，不证明双方处境完全相同。
5. 回应顺序以情绪承接、允许感受存在、轻量鼓励为主。
6. 不主动给行动清单；用户主动选择解决方向后才展开建议。

示例语气：你已经努力解释了很多次，却还是觉得没被听见，这种委屈值得被认真对待。

该例是策划文案，不是来自真实检索的引用。

### 4.5 解决分支

沿用相似主题检索与来源核验流程。先简短确认处境，再给少量可选建议，说明适用条件。用户可以选择其中一项、继续补充或回到共鸣。

建议使用“如果你愿意，可以试试……”等允许拒绝的表达，避免“你必须”“你就是想太多”。不对他人意图作确定判断，不诊断用户或关系中的其他人。

建议不超过三项作为首屏设计原则；涉及复杂处境时先允许补充背景，不追求一次回答所有问题。

### 4.6 静默倾听分支

1. 进入后只展示纸团 IP 的倾听状态和必要的输入控件。
2. 用户继续输入时，IP 可以轻微点头；不插入 AI 对话文本、摘要、追问或分析。
3. 固定操作按钮为 **说完了**，由用户主动触发。
4. 点击后才允许分析与提炼；交互版用明确标注的演示规则模拟该结果。
5. 提炼后让用户确认表达是否准确，并提供共鸣、建议或释放的后续选择。

录音状态、上传失败等必要系统反馈可以显示，但不可伪装成 AI 陪伴文字。切换回应方向属于用户主动结束静默流程，应明确保留此前输入。

### 4.7 烦恼重点确认

避免直接使用“真正根源”“你其实就是”等断言。面向用户用“这次最想丢掉的烦恼”或“烦恼重点”命名。

1. 显示候选短句，允许编辑、重写或手动填写。
2. 用户点击确认后，才把它交给释放玩法。
3. 不要求用户认可 AI 的解读；“不太对，我自己写”和不写字开始都是等价路径。
4. 依据原规范，目标最多 16 字、建议 4–12 字；超长提示缩写。空白是合法释放选项，不伪造重点。
5. 若内容过长，优先由用户缩写，不静默改变含义；视觉上允许换行。

### 4.8 纸人靶子

- 靶子内部持续显示已确认的烦恼重点。
- 点击“直接投过去”，纸团飞向纸人靶子，纸人晃动反馈；纸团会补充，支持连续重复投掷。
- 不按次数或倒计时自动倒下；用户点击“结束发泄”后，纸人倒下，再进入结束页。
- 反馈围绕烦恼文字与纸质形象，不把现实人物照片、姓名设为攻击对象。
- 用户可以随时暂停、重来或结束，不用分数与倒计时催促。
- 结束时提供回到首页、再玩一次或选择其他玩法。

### 4.9 冰块

- 冰块内部显示同一个已确认的烦恼重点。
- 用户操作引发裂纹、碎裂或原稿规定的变化。
- 文字在互动期间保持可读；结束后可以消散，但确认页始终可返回。
- 不把击碎次数当成情绪改善指标，不使用“烦恼已经彻底消失”的承诺。

### 4.10 冲水：一口气冲走

- 可选“卡通马桶”或“水流漩涡”，使用原包道具；切换表现不改动已确认文字。
- 点击“冲走这些”后播放约 1.5 秒的纸团旋转缩小与消散反馈。
- 动画结束后清空本轮便签，可再来一次、结束或选择其他玩法；不清除倾诉消息和背景小纸条。
- 允许不写字直接体验，不要求先调用模型或填写身份信息。

### 4.11 结束与退出

结束文案允许用户仍然难受，例如“可以先在这里歇一会儿”。感受记录和保存均可跳过。不默认触发下一轮倾诉。

会话退出时，如存在未保存内容，提供继续、放弃或主动保存到本机的选择。刷新后的恢复行为取决于用户是否保存，不默认在后台保存敏感内容。

## 6. UI 与素材实施要求

### 6.1 还原原则

以原稿与原素材为唯一视觉基准，保留温暖治愈的卡通画风、纸团角色特征和河岸场景。禁止用通用图标、Emoji 或临时重绘替代原 IP 后声称精确还原。

按原稿提取颜色、文字、间距、圆角、阴影和动效变量，记录在设计说明中。两项首页入口保持居中对齐，交互状态沿用原设计语言。

### 6.2 移动端规范

- 优先验证 360、390、430 CSS 像素宽度，并覆盖 320 像素窄屏与桌面居中展示。
- 正文保持可读，对比度不足时在保留画风的前提下调整并记录。
- 主要触控目标建议至少 44 × 44 CSS 像素。
- 适配刘海安全区、底部手势区和软键盘；发送与说完了按钮不可被遮挡。
- 页面可滚动，长文本和多图不会撑破布局。
- 按钮具备可访问名称、键盘焦点与禁用状态；反馈不只依赖颜色。
- 尊重减少动态效果设置，IP 倾听与释放反馈提供低动态表现。

### 6.3 素材入库

完整原文件保留在 `design-kit/`，Web 直接引用 `design-kit/assets/`，不复制或修改原 PNG。原目录 `design-kit/index.html` 可独立查看所有页面与素材。

实际核验素材：横版 Logo、图形标、文字标、方形图标；8 种 IP 情绪、8 个动作姿态；8 个玩法道具；1 张首页河岸插画。已对全部 76 个文件与 ZIP 内容作 SHA-256 比对。

IP 动作目前据摘要属于关键姿态，不代表连续动画。Web 可利用这些姿态进行轻量切换，若制作额外过渡须单独标识为实现扩展。

不得公开包含私人信息的截图、真实会话记录、未授权字体或第三方受限素材。

## 7. 第一版技术方案

### 7.1 方案选择

用户已选择：先交付无密钥的前端交互版，真实 AI 和网络检索以后通过服务端扩展。

实现建议采用静态 HTML、CSS 与 JavaScript 模块。它不依赖账号或私钥，可在本地静态服务器和静态托管环境中运行。若原稿交互复杂到需要组件框架，可在不改变体验范围的前提下调整并记录。

完整前后端方案能提供真实回复、OCR 与检索，但涉及模型与检索服务、密钥管理、数据告知和持续费用，超出当前已确认交付。只做静态截图则无法验证静默倾听与释放闭环，因此不作为本次 Web 方案。

### 7.2 演示能力边界

- 文字：真实输入、编辑和流程流转；回复内容显式标为演示。
- 图片：真实选择、本地预览、删除和校验；没有 OCR 时不声称已读懂截图。
- 语音：采用浏览器支持的能力，启动前说明是否会调用浏览器厂商服务；不支持或用户不愿使用时回退到文字。若提供录音而没有转写，明确显示“录音未转写”，不据此生成内容分析。
- 共鸣与建议：使用预设样例或透明规则模拟，不冒充真实模型推理。
- 检索：样例来源独立标注，不伪造社媒用户、真实引用和来源链接；不支持时直接显示未接入。
- 烦恼提炼：仅从已输入文本做演示处理，用户必须确认。
- 释放：本地交互可真实体验。

### 7.3 状态与数据

会话包含：会话 ID、创建时间、输入项、当前方向、流程状态、候选重点、确认重点、可选的结束感受。输入项包括文本、图片本地引用或录音状态。

推荐流程状态：`composing → choosing → empathizing / solving / listening → summarizing → confirming → releasing → finished`。

- `listening` 状态禁止触发分析和自动回复。
- `summarizing` 只能由用户点击说完了，或在其他方向中明确请求提炼时进入。
- `releasing` 必须经过目标选择；允许确认文本或显式选择空白，直接从首页进入者同样有空白路径。
- 切换方向保留输入，作废旧方向未完成的异步请求，避免旧回复串入新分支。
- 本地存储仅在用户主动保存时写入；附件默认不持久保存。
- 退出、移除附件或清空数据时释放对象 URL；页面录音结束后停止麦克风轨道。

### 7.4 后续服务接口建议

- `POST /api/respond`：输入去身份化内容与用户方向，返回回应与可选来源；静默状态不得调用。
- `POST /api/summarize`：在用户主动结束讲述后返回候选重点，不直接写成已确认重点。
- `POST /api/search`：只接收用户审核过的关键词，返回真实标题、链接、平台、发布时间（如可得）、获取时间和短摘要。
- `POST /api/transcribe`：经过明确同意后上传音频，返回转写与失败原因。
- `POST /api/ocr`：经过明确同意后处理图片，提取文本可由用户修正。

以上只是接口契约建议，当前没有部署或实现。服务密钥仅存服务端，不进入前端、日志、截图或仓库。

## 8. 隐私与内容边界

演示版本默认不上传输入，不接入行为追踪。不把敏感内容作为 URL 参数、错误日志或分析事件。

实际联网版本在首次发送前说明接收方、用途、保存期限和删除方式。搜索关键词默认去除姓名、电话、公司、精确地址等身份线索，并由用户确认。

浏览器语音识别可能使用浏览器厂商服务，不能笼统标为完全离线；没有确认运行机制时优先采用文字回退。

面向现实中的即时危险内容，后续真实服务应提供简短、直接的支持提示，鼓励联系身边可信任的人或当地紧急服务；不以释放小游戏替代紧急支持。具体策略需在真实服务上线前单独验证，交互演示不宣称具备自动识别能力。

## 9. 验收要求

### 9.1 核心流程

- 首页两项入口文案正确、居中，视觉与原稿对应。
- 首次输入后先选择方向，不默认出现 AI 回复。
- 共鸣分支不自动输出解决清单；解决分支使用非说教表达。
- 静默期间连续多次输入均无 AI 文本回复；只有主动说完后才出现提炼。
- 用户可以修改或否定重点，或主动选择空白；未经确认不能自动进入带文字的释放玩法。
- 纸人和冰块显示同一个已确认短句，长文字不溢出。
- 各玩法可以结束、重来和返回；纸人连续投掷不自动倒下，结束时倒下；冲水只删除本轮便签。
- 直接进入释放也能手动确认重点，完成完整闭环。

### 9.2 真实性与失败分支

- 每个演示回复与来源样例都能被用户识别为演示。
- 图片只预览时，不声称完成图片理解。
- 无麦克风权限、语音不支持、无文字转写均有可用回退。
- 大图、错误格式、空输入、超长输入、存储失败均显示明确提示。
- 原始输入、图片和录音不进入版本控制；清空本地数据后无法再从界面读取。

### 9.3 视觉与设备验证

已建立页面与素材对应清单，再对核心页面截图比对。至少验证首页、输入、方向选择、静默倾听、重点确认、纸人、冰块、结束和隐私管理。

在可用浏览器中检查 iOS Safari 与 Android Chrome 的响应布局、触控、滚动、安全区和权限降级。若无法运行真机或浏览器验证，在交付说明中明确限制，不将源码检查称为端到端通过。

## 10. 验证指标与迭代

第一版以定性可用性验证为主，不默认接入统计。后续如采集指标，须由用户知情且仅记录必要事件，不上传倾诉正文。

关注：能否理解三方向差异、静默期间是否感到被打断、重点是否被认可、释放玩法是否容易结束、是否能识别演示边界。

流程指标可包括选择方向后的完成率、说完了到重点确认的完成率、重点重写比例和自愿结束比例。它们用于发现交互问题，不用来推断心理健康改善。情绪前后记录完全自愿，不要求“变好”。
